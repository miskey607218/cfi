核心能力

三大模块协同工作，覆盖运行时安全监控的完整链路

🛡

CFI 控制流校验

实时检测间接调用/跳转/返回指令的目标地址是否合法。 支持三级等价类缩小：全地址空间 → 静态函数头集合 → 调用点敏感 (Call-Site) → 起源敏感 (Origin)。 违规行为可配置为 SIGKILL 强制终止。

📈

DFI 三层数据流追踪

L3（指针加载）→ L2（解引用）→ L1（间接跳转执行）， 逐层记录寄存器值与内存地址，完整还原函数指针从数据段 到间接跳转的全链路传播过程。

⚡

攻击场景模拟

内置 7 种 CFI 违规攻击：栈溢出覆写函数指针、返回地址劫持、 vtable 破坏、堆溢出、双重指针劫持等。 SAFE/ATTACK 双模式，通过 Web 前端一键执行并实时查看检测结果。

🌎

Web 可视化面板

Chart.js 动态图表（跳转类型饼图、DFI 层柱状图、正确率时间线）， CFI 事件表（搜索/过滤/分页），DFI 数据流链卡片。 攻击控制台支持异步编译、执行、结果轮询。

🔍

静态数据流分析

解析 objdump 反汇编，构建基本块 CFG，迭代求解 reaching definitions， 为每个间接跳转站点生成 def-use 链，识别跨函数/未定义的数据流路径。

⚙

灵活运行模式

Train — 收集正常行为基线数据   Enforce — 强制校验，违规立即终止   Hybrid — 自适应策略，根据等价类大小动态选择方法

系统架构

编译 → 静态分析 → eBPF 运行时监控 → 数据可视化 完整流水线

Pipeline:
gcc test.c/attack.c → .so
 └ objdump -d → .txt
    └ transformToCsv.py → jump_analysis.csv
       └ dataflow_analysis.py → register_dfi_*.csv
          └ dfi_monitor.py (eBPF uprobes) → output/*.csv

项目档案

完整的测试场景覆盖与攻击场景分类

test.c — 17 种正常间接跳转场景

#场景跳转模式关键指令
01全局函数指针调用GOT 间接call *ptr(%rip)
02局部函数指针调用寄存器间接call *%rax
03函数指针表调用数组索引间接mov array(,%rax,8),%rax → call *%rax
04栈上函数指针RBP 相对寻址mov -N(%rbp),%rax → call *%rax
05vtable 模拟结构体成员mov OFFSET(%rax),%rax → call *%rax
06回调函数指针传参参数寄存器call *%rdi
07间接跳转（尾调用）jmp 间接jmp *%rax
08带返回值的间接调用rax 覆盖验证call *%rax (rax=retval)
09多参数间接调用三参数调用call *%rax (rdi/rsi/rdx)
10volatile 强制内存路径栈加载栈 → mov → call *%rax
11条件选择间接调用jcc + 间接if-else fptr → call *%rax
12switch-case 分发跳转表风格多路分支 fptr
13LEA 计算目标地址lea + 间接lea target(%rip),%rax → call *%rax
14嵌套返回链多层 call/ret返回地址栈追踪
15双重指针间接调用两级解引用mov (%rax),%rax → call *%rax
16函数返回指针再调用跨调用数据流rax 由上层 call 定义
17嵌套结构体函数指针多层 struct深层成员访问

attack.c — 7 种 CFI 攻击场景

#攻击名称攻击原理违规 CFI 类型严重度
01全局指针劫持setup 设置合法指针 → ATTACK 篡改为 evil → call 时 saved≠raxINDIRECT_CALLHIGH
02双重指针劫持通过二级指针间接修改最终调用目标INDIRECT_CALLMEDIUM
03条件分支劫持攻击者控制分支条件，走入持有非法指针的路径INDIRECT_CALLMEDIUM
04结构体函数指针替换模拟 vtable 破坏：结构体 action 成员被篡改INDIRECT_CALLHIGH
05返回指针劫持函数返回合法指针后，攻击者替换再调用INDIRECT_CALLHIGH
06堆回调替换malloc 后的函数指针被篡改INDIRECT_CALLHIGH
07函数指针表投毒初始化表后篡改某一槽位INDIRECT_CALLMEDIUM
